# AffiliateOS — как построить такую систему с нуля

Это инструкция по воспроизведению, а не передача доступа. Здесь нет ни одного
ключа и ни одной ссылки на чужую базу: вы поднимаете **свою** инфраструктуру,
свои аккаунты, свою базу данных. Всё, что описано ниже, собирается из бесплатных
или почти бесплатных тарифов.

Дочитайте до раздела «Грабли» перед тем, как что-то запускать. Там собраны
поломки, каждая из которых уже случалась и стоила дней простоя. Знать их заранее
дешевле, чем встретить.

---

## 1. Что эта система делает

Задача: находить сайты, которые **уже льют трафик на букмекеров**, доставать их
контакты и предлагать партнёрскую программу. Не «сайты про спорт вообще», а
именно тех, кто уже монетизирует беттинг-аудиторию — они понимают, о чём речь,
и им не нужно ничего объяснять с нуля.

Система полностью автономна. Никто не нажимает кнопок: она сама ищет, сама
оценивает найденное, сама достаёт почту, сама пишет письма и сама держит лимиты.
Человек нужен для двух вещей — отвечать тем, кто откликнулся, и решать, что
делать с пограничными случаями.

Порядок величин, чтобы понимать масштаб: одна работающая система за несколько
месяцев набирает **8000+ сайтов** и отправляет **3500+ писем**, при затратах,
близких к нулю (бесплатные тарифы плюс опционально DataForSEO).

---

## 2. Архитектура

Четыре независимых источника лидов. Независимость здесь принципиальна: у каждого
своя очередь, свой дневной лимит и свой выключатель, поэтому поломка одного не
останавливает остальные.

### Пайплайн 1 — поиск по ключевым словам (основной, бесплатный)

Ищет в DuckDuckGo по коммерческим запросам («betting tips nigeria», «bookmaker
review kenya»), прогоняет выдачу через LLM-оценщика, сохраняет подходящее.
Самый дешёвый и самый объёмный источник.

### Пайплайн 2 — брендовый трафик (бесплатный)

Ищет по запросам вида «mostbet apk», «1win скачать», «bet9ja login». Идея в том,
что **выдача сама себя фильтрует**: первое место по брендовому запросу почти
всегда занимает сам оператор, а места со 2-го по 50-е — это почти исключительно
партнёры, перехватывающие этот трафик. Новостные сайты и статистика туда не
попадают, им незачем. То есть выдача по чужому бренду — это готовый список
партнёров, и отбор сделал поисковик, а не вы.

Человек, который ищет «mostbet apk», уже выбрал бренд и идёт устанавливать
приложение. Намерение максимальное, разогревать никого не нужно.

### Пайплайн 3 — DataForSEO (платный, опциональный)

Единственный источник, который стоит денег. Работает через API DataForSEO:
берёт конкурентов по выдаче, их ключевые слова и пересечения ссылочных профилей
нескольких букмекеров. Домен, который ссылается сразу на трёх разных
букмекеров, — партнёрский сайт с вероятностью, близкой к единице; больше так не
ведёт себя никто.

Стоит примерно **$0.024 за запрос плюс $0.000036 за строку**. Запускается
руками, крупными редкими партиями. Намеренно **не** ставится на расписание —
автоматический платный поиск это способ незаметно потратить весь депозит.

### Пайплайн 4 — Telegram-каналы

Ищет каналы, вытаскивает контакт владельца из описания, готовит карточку.
Ничего не отправляет автоматически: только собирает и показывает.

### Общий конвейер

```
поиск → LLM-оценка → сохранение лида → поиск контактов → проверка адреса
      → очередь отправки → отправка → отслеживание ответов
```

## 3. Из чего это собрано

| Слой | Сервис | Тариф | Зачем |
|---|---|---|---|
| База данных | Supabase (PostgreSQL) | бесплатный | все данные, plus REST API «из коробки» |
| Логика | Supabase Edge Functions (Deno) | бесплатный | ~35 функций, каждая — один этап |
| Планировщик + хостинг | Cloudflare Workers | бесплатный | запускает функции по расписанию, отдаёт дашборд |
| LLM-оценщик | Groq | бесплатный | решает, партнёр перед нами или мусор |
| Поиск | DuckDuckGo (парсинг) | бесплатно | основной источник выдачи |
| Поиск (резерв) | SerpApi | 100/мес бесплатно | подстраховка, когда DDG отдаёт пустоту |
| Ссылочные данные | DataForSEO | оплата по факту | только для платного пайплайна |
| Почта | Gmail + App Password | бесплатный | отправка по SMTP, чтение ответов по IMAP |
| Проверка адресов | MillionVerifier | от $27 за 10k | отсев мёртвых адресов до отправки |
| Извлечение текста | Jina Reader | бесплатный лимит | достаёт контакты со сложных страниц |
| Уведомления | Telegram Bot API | бесплатно | алерты и ежедневный отчёт |

Обязательный минимум для старта: **Supabase + Cloudflare + Groq + Gmail**.
Всё остальное подключается по мере надобности.

## 4. Установка

### Шаг 1. Supabase

1. Создайте проект на supabase.com. Запишите **Project Reference** (строка вида
   `abcdefghijklm` в URL проекта).
2. В Settings → API возьмите два ключа:
   - `anon` — публичный, попадёт в браузер, это нормально, его защищает RLS;
   - `service_role` — **секретный**, только для серверных функций. Он обходит
     все политики доступа. В браузер он не попадает никогда.
3. Settings → Access Tokens: создайте personal access token для деплоя из CI.

### Шаг 2. Схема базы

Схема разложена на миграции, которые применяются **строго по порядку имён
файлов**. Порядок — часть логики: поздние миграции опираются на таблицы,
созданные ранними.

```bash
supabase link --project-ref ВАШ_REF
supabase db push
```

Что создаётся, по смыслу:

- `leads` — центральная таблица. Сайт, контакты, гео, оценка, стадия, пайплайн.
- `email_log` — что и кому реально ушло. Основа дедупликации.
- `send_queue` — очередь с временем отправки.
- `error_log` — журнал всех этапов. **Ваш главный инструмент диагностики.**
- `pipeline_limits` — дневной лимит и пауза для каждого пайплайна.
- `keywords` — пул поисковых запросов, разложенный по слоям и гео.
- `suppression_list` — кому не писать никогда.
- `source_health` — здоровье источника выдачи, защита от бана.
- `app_state` — курсоры и счётчики между запусками.
- `brand_*` — таблицы брендового пайплайна: бренды, ключи, официальные домены.
- `dfs_*` — таблицы платного пайплайна.
- `tg_*` — Telegram-часть.

### Шаг 3. Секреты

Задаются один раз, лежат на стороне Supabase, в репозиторий не попадают:

```bash
supabase secrets set GROQ_API_KEY=... --project-ref ВАШ_REF
supabase secrets set GMAIL_USER_MAIN=... GMAIL_PASS_MAIN=... --project-ref ВАШ_REF
```

Полный список (`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` подставляются
платформой сами):

**Обязательные**
- `GROQ_API_KEY` — оценщик. Без него не сохранится ни один лид.
- `GMAIL_USER_MAIN`, `GMAIL_PASS_MAIN` — почта. Пароль именно **App Password**,
  а не пароль от аккаунта; для этого нужна включённая двухфакторная авторизация.

**Настоятельно рекомендуемые**
- `GROQ_KEY_2`, `GROQ_KEY_3` — второй и третий ключ Groq. Причина в разделе
  «Грабли»: на бесплатном тарифе одного ключа не хватает.
- `ALERTS_BOT_TOKEN`, `ALERTS_CHAT_ID` — алерты в Telegram.

**Опциональные**
- `DFS_LOGIN`, `DFS_PASSWORD` — DataForSEO.
- `SERPAPI_KEY_1..3` — резервный поиск.
- `MILLIONVERIFIER_KEY` — проверка адресов.
- `JINA_API_KEY` — извлечение контактов со сложных страниц.
- `ANTHROPIC_API_KEY` — более качественный оценщик вместо Groq на больших
  очередях.
- `YOUTUBE_API_KEY`, `OUTLOOK_USER`/`OUTLOOK_PASS` — дополнительные каналы.

### Шаг 4. Деплой функций

```bash
for fn in edge-functions/*.ts; do
  name=$(basename "$fn" .ts)
  mkdir -p "supabase/functions/$name"
  cp "$fn" "supabase/functions/$name/index.ts"
  supabase functions deploy "$name" --project-ref ВАШ_REF --no-verify-jwt
done
```

`--no-verify-jwt` обязателен: функции вызывает планировщик, а не залогиненный
пользователь.

Автоматизируйте это через GitHub Actions. Важен порядок: **сначала миграции,
потом функции**. Функция, задеплоенная раньше своей таблицы, падает на каждом
запуске до следующего деплоя.

### Шаг 5. Планировщик и хостинг

Cloudflare Worker делает две вещи: отдаёт дашборд и дёргает функции по
расписанию.

```bash
npm install -g wrangler
wrangler login
wrangler deploy
```

Расписание в `wrangler.jsonc`:

```jsonc
"triggers": {
  "crons": ["*/2 * * * *", "*/3 * * * *", "*/15 * * * *", "0 7 * * *", "*/7 * * * *"]
}
```

Как раскладывается работа:

- **каждые 2 мин** — отправка писем, пополнение очереди, поиск контактов
- **каждые 3 мин** — поиск по ключам, формы, этапы платного пайплайна
- **каждые 7 мин** — дополнительные источники
- **каждые 15 мин** — лимиты, follow-up, проверка адресов, Telegram
- **07:00 UTC** — ежедневный отчёт

**На бесплатном тарифе Cloudflare ровно 5 cron-триггеров.** Шестой не выдаёт
ошибку — он просто молча никогда не запускается. Именно так однажды выяснилось,
что целый канал не работал неделями. Поэтому этапы сгруппированы по пяти тикам,
а не разнесены по своим.

### Шаг 6. Дашборд

Одностраничное приложение, `index.html`, обращается к Supabase напрямую из
браузера с anon-ключом. Раздаётся тем же воркером.

Пароль на вход включается секретом `DASHBOARD_PASSWORD`; пока он не задан,
дашборд открыт, и это сделано намеренно — чтобы деплой не запер вас снаружи до
того, как вы всё настроили.

## 5. Что обязательно поменять

Если вы копируете этот код, в нём остаются чужие идентификаторы. **Никакой
связи с чужой базой быть не должно** — замените всё перечисленное, иначе ваша
система будет писать в чужой проект.

| Файл | Что заменить |
|---|---|
| `worker.js` | `DEFAULT_SUPABASE_URL`, `DEFAULT_ANON_KEY`, `SUPABASE_ANON`, адрес `web_app` в кнопках бота |
| `index.html` | `SUPABASE_DIRECT`, `SUPABASE_KEY` |
| `edge-functions/process-queue.ts` | контакт менеджера в шаблонах писем |
| `edge-functions/draft-tg-message.ts` | контакт менеджера |
| `edge-functions/process-form-queue.ts` | контакт менеджера |
| миграции с сидами | бренды, ключевые слова, гео — под вашу программу |

**Отдельно про ключи в `index.html`.** В исходном виде там лежат открытым
текстом ключи Groq и SerpApi. Это ошибка, а не образец: их видит любой, кто
откроет исходный код страницы. Anon-ключ Supabase там быть может — он для этого
и предназначен, его ограничивает RLS. Остальные ключи нужно убрать, а вызовы,
которые их используют, перенести в edge-функцию. Если вы строите с нуля — просто
не повторяйте этого.

## 6. Как это работает по этапам

### Поиск

Запросы разложены по слоям: широкие («betting tips»), узкие («bookmaker review
nigeria»), точные фразы. У каждого гео свой набор. Курсор по пулу ключей
хранится в базе, поэтому запуски не топчутся на одном месте.

Тонкость, которая экономит много времени: **первая страница выдачи почти
бесполезна**. Там сидят крупные сайты, до которых уже все достучались. Реальный
выход дают страницы 2–4.

### Оценка

Пачка результатов уходит в LLM с жёстким промптом. Задача — не «хороший ли это
сайт», а «владеет ли этот сайт аудиторией и монетизирует ли беттинг».

Что модель обязана отсекать:
- самих букмекеров (это конкуренты, а не партнёры);
- **машинно-сгенерированные сайты** — SEO-инструменты, whois-сервисы, скраперы
  PDF и APK. Они ссылаются на десятки букмекеров как побочный эффект скрейпинга,
  поэтому по ссылочному графу выглядят прекрасно, и поймать их может только
  модель;
- сайты-отзовики и агрегаторы проверок — они ранжируются по брендовым запросам
  именно потому, что там проверяют бренды, но партнёрского трафика не продают;
- сайты вне вашей гео-зоны.

Правило, которое стоит держать в промпте дословно: *если решение опубликовать
страницу принимал не человек — это не партнёр, сколько бы букмекеров он ни
упоминал.*

### Поиск контактов

По очереди: `mailto:` на странице → страница контактов → JSON-LD → подвал →
деобфускация (в том числе Cloudflare-защита почты) → соцсети.

Отдельно отсеиваются **контакты регистраторов и хостеров**: `support@ps.kz` —
это не владелец сайта, а его провайдер.

### Отправка

- Дневной лимит на пайплайн, отдельно для каждого.
- Интервалы случайные, а не равные — ровный такт выглядит как робот.
- Дедупликация **по адресу, а не по сайту**: один и тот же ящик часто обслуживает
  десяток доменов, и человек не должен получить от вас десять писем.
- Тема выбирается по идентификатору лида, а не случайно, — иначе повторная
  попытка придёт под другой темой.
- Персонализация по домену и по запросу, на котором сайт был найден.

### Ответы

IMAP забирает входящие, сопоставляет с исходным письмом по `Message-ID`,
классифицирует и останавливает последовательность для тех, кто ответил.

## 7. Настройка под свою программу

1. **Ключевые слова.** Замените сиды в миграциях на свою вертикаль и свои гео.
   Это определяет всё остальное.
2. **Официальные домены.** Заполните список доменов операторов, которым писать
   не нужно. Список должен быть **явным**, а не по шаблону имени: `1win.fyi` —
   это партнёр, а `1win.com` — оператор, и по форме домена их не различить.
   Любое правило по маске либо пропустит операторов, либо выбросит лучших
   кандидатов.
3. **Шаблоны писем.** Коротко, с указанием конкретного сайта и запроса, с одним
   понятным следующим шагом. Длинное письмо не читают.
4. **Лимиты.** Начните с малого — 20–30 писем в день с нового домена. Резкий
   старт с большого объёма убивает репутацию домена.
5. **Языки.** Под каждую крупную гео стоит завести свой вариант письма.

## 8. Грабли

Каждый пункт ниже — реально случившаяся поломка. Почти все они **не выдают
ошибку**, а просто тихо обнуляют результат, и в этом их главная опасность.

### Groq: `max_tokens` резервируется целиком

На бесплатном тарифе лимит 6000 токенов в минуту, и `max_tokens` **вычитается
из него независимо от того, сколько модель реально ответила**. Один запрос с
`max_tokens: 4096` съедает почти всю минуту — все остальные получают 429.

Считайте размер по задаче: `120 × количество_элементов + запас`. Ставьте
несколько ключей и чередуйте их.

### Модель могут снять с обслуживания

Однажды провайдер убрал модель, зашитую строкой в семи функциях. Все ответы
превратились в `404 The model does not exist`, и вся система встала за один шаг:
сайты продолжали находиться, но ни один не мог быть оценён, а прогон, который
ничего не оценил, ничего и не сохраняет.

**Держите список моделей, а не одну строку.** При ответе «модели не существует»
переходите к следующей. Ротация ключей здесь не помогает — все ключи ответят
одинаково, это отдельная ось отказа.

### Повтор через 2 секунды не помогает при 429

Лимит считается по **скользящей минуте**. Если все ключи исчерпаны сейчас, через
две секунды они исчерпаны ровно так же. Лестница пауз должна быть порядка
0 / 5 / 20 секунд.

### DuckDuckGo банит за темп

Общий исходящий IP на все функции. Превышение темпа примерно втрое убило выдачу
на два дня: каждый запрос возвращал пустую страницу.

Нужны: стабильный User-Agent в пределах сессии, переиспользование токена сессии,
случайные задержки, ограничение параллелизма, общий детектор деградации на все
функции. Защищается общий IP, а не квота отдельной функции.

### Детектор бана легко сделать слишком чутким

Обратная сторона: наш детектор замораживал поиск на 45 минут, когда «мало
результатов». Точные фразы дают мало результатов **всегда** — это норма, а не
бан. В итоге из десяти запусков реально искали два, и один удачный запуск,
нашедший девять сайтов, замораживал систему.

Реагируйте на **полностью пустую** выдачу подряд, а не на «мало». Первая пауза
короткая, длинная — только при повторе.

### PostgREST отдаёт максимум 1000 строк

Запрос без явной постраничности **молча** обрежется до 1000. Если на этом
построена дедупликация, вы начнёте писать повторно тем, кому уже писали, и
никакой ошибки при этом не увидите.

### Cloudflare: 5 cron-триггеров на бесплатном тарифе

Шестой молча не работает. Группируйте этапы по существующим тикам.

### Порядок миграций и деплоя

Миграции применяются по именам файлов и **до** функций. Функция, задеплоенная
раньше своей таблицы, падает на каждом запуске.

### Тире в теме письма

Заголовки писем чистятся до ASCII. Длинное тире при этом **удаляется вместе с
пробелами вокруг**, и тема «site.com — партнёрство на 5 минут» превращается в
«site.com партнёрство на 5 минут». В теме используйте обычный дефис; в теле,
которое уходит в UTF-8, длинное тире живёт нормально.

### Зеркала операторов

Операторы держат десятки доменов в разных зонах, чтобы переживать блокировки.
Написать оператору вместо партнёра — стыдно и бесполезно.

Правило, которое работает: **голый бренд без добавок** — это оператор
(`1win.xyz`), а добавка доказывает обратное (`1winbonus.com` — партнёр).
Осторожно, здесь легко ошибиться в противоположную сторону: проверка «домен
содержит бренд» пометит партнёра как оператора, то есть выбросит именно лучших
кандидатов.

Два случая, которые легко упустить:
- бренд может быть разрезан доменом и зоной: `meridian.bet` читается как
  «meridianbet» и является оператором;
- голый бренд в **страновой** зоне (`sportpesa.co.za`) — почти всегда локальный
  сайт оператора: партнёр не может зарегистрировать там голый бренд, так же как
  и в `.com`.

### Не тяните всю базу в браузер разом

Дашборд загружал все лиды целиком, страницами по 1000, и рисовал только после
последней. При 8500 лидах на быстром канале это выглядит мгновенно, а на
медленном — как сломанная страница: нули на экране и никакой возможности
отличить «грузится» от «пусто». Рисуйте первую страницу сразу, остальные
догружайте следом.

### Кэш страницы

`no-store` в заголовках запрещает браузеру хранить файл, поэтому каждое открытие
качает страницу целиком заново. Для дашборда почти всегда нужен `no-cache` —
это «перепроверь перед использованием», а не «не храни»: при неизменной странице
приходит пустой ответ «не изменилось».

### Не делайте непроверенный путь основным

Самая дорогая ошибка из всех. При попытке починить доступ из одной страны
загрузка библиотеки была переведена на новый маршрут — и сайт перестал
открываться отовсюду. Причина тонкая: маршрут, который отвечает `200` с
HTML-страницей ошибки вместо скрипта, **не вызывает `onerror`** — браузер такой
ответ принимает, не может его разобрать, и резервный вариант не срабатывает
никогда.

Новый путь всегда делайте запасным, а рабочий оставляйте основным.

## 9. Эксплуатация

**Что смотреть ежедневно** — по `error_log`:

- сколько строк за сутки записал каждый сервис (отсутствие сервиса в списке —
  это и есть ответ);
- сколько прогонов реально искали, а сколько сами себя притормозили;
- сколько кандидатов оценено — `analyzed=0` при ненулевом `found` означает
  сломанный оценщик;
- сколько писем ушло и по каким пайплайнам.

**Правило, которое стоит усвоить сразу:** в этой системе почти всё ломается
беззвучно. Ошибка в журнале — это подарок. Обычная поломка выглядит как ноль в
отчёте при полностью зелёных статусах. Поэтому логируйте по каждому прогону
цепочку чисел `найдено → оценено → сохранено → контактов`: она показывает, на
каком именно шаге всё исчезло.

**Диагностика, когда «всё по нулям»:**

1. Записал ли хоть один сервис хоть что-то за сутки? Нет — встал планировщик.
2. Находятся ли сайты (`found` больше нуля)? Нет — проблема с источником выдачи.
3. Оцениваются ли они (`analyzed`)? Нет — проблема с LLM: ключ, лимит, модель.
4. Есть ли контакты? Нет — проблема с извлечением.
5. Наполняется ли очередь? Нет — смотрите лимиты, паузу и дедупликацию.

## 10. Правовая сторона

Это холодная рассылка по B2B-адресам, и относиться к ней надо серьёзно.

- В каждом письме — реальный способ отказаться от рассылки, и он должен
  работать. Список отказов (`suppression_list`) существует именно для этого.
- Проверяйте требования той юрисдикции, где находятся получатели: GDPR в Европе,
  CAN-SPAM в США, локальные правила в остальных странах. Требования различаются
  существенно.
- Не пишите повторно тем, кто попросил не писать. Технически это и есть
  `suppression_list`, и он должен проверяться перед каждой отправкой.
- Реклама азартных игр регулируется отдельно и по-разному в разных странах.
  Убедитесь, что ваша партнёрская программа разрешена там, куда вы пишете.
- Пишите правду о том, что предлагаете.

Соблюдение этих правил — это не только законность, но и доставляемость:
домен, с которого шлют спам, перестаёт доходить до адресатов за считанные дни.
